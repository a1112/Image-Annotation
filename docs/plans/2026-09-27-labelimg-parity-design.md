# labelImg C++ 标注能力对齐设计

## 目标与基线

以 `L:\project\labelImg` 的 C++ 版（含其 Python AI 桥接）为行为参考，把标注能力整合到现有 React/Tauri 工作台。现有数据集、原生标注、修订、质检和快照仍是项目的唯一工作流；不另起一个独立编辑器。用户确认沿用当前布局，并包含 ONNX 检测以及点、框、文本 AI 提示。

## 参考功能与现状

| 能力 | 当前项目 | 对齐目标 |
| --- | --- | --- |
| BBox、Polygon、分类 | 基础绘制、移动、顶点拖动、保存 | 补齐标签选择、形状校验和编辑一致性 |
| 其他形状 | 无 | 旋转框、圆、线、折线、单点、多点、掩码，含增删顶点 |
| 对象操作 | 单选、复制、删除、框移动、少量快捷键 | 多选、全选、撤销/重做、删除全部、可见性、困难标记、标签筛选/排序、颜色与属性、前一张框复制 |
| 图片导航 | 首 120 张，缩略条首 12 张 | 可遍历项目全部图片，搜索/定位，前后切换及未保存处理 |
| 查看 | 缩放、适配窗口、平移 | 适配宽度、亮度、快捷键、标注定位和显示开关 |
| 文件格式 | 原生 JSON、YOLO/VOC 写回、COCO/YOLO 快照导出 | LabelMe JSON、CreateML 读写、外部标注载入，格式兼容预检与明确错误 |
| 状态 | 保存、质检；空格键仅改本地文字 | 自动保存设置、保存并下一张、可持久化的验证状态 |
| AI | 工具占位，无推理 | 本地 ONNX 检测与点/框/文本提示，进度、取消、结果校验、合并与撤销 |

## 方案选择

1. **扩展现有 React/Tauri 工作台（采用）**：前端统一处理形状几何、交互和历史；Rust 管理原生存储、格式转换和 AI 子进程。能与现有项目/质检/快照保持一致，代价是需要逐项实现画布操作。
2. **从工作台启动 C++ 编辑器**：可复用成熟交互，但双应用必须同步图片、标签、修订、质检与撤销状态，失败时易出现两份真相。
3. **整体移植 Qt 核心**：可以追求代码层复用，但 UI/运行时迁移成本高，且与现有 Tauri 架构冲突。

## 数据与格式

给 `AnnotationObject` 增加明确的形状类型和几何数据，同时保留当前 `bbox`/`polygon` 的读取兼容。形状元数据保留标签、类别 ID、困难标记、分组、描述、颜色、flags、AI 来源/置信度；画布可见性作为界面状态，不因过滤而删除对象。原生 JSON 和 SQLite 修订无损保存这些字段。LabelMe JSON 支持往返；VOC、YOLO 和 CreateML 仅写入其可表达的几何，不允许静默丢失。保存前先预检目标格式和所有对象；不兼容时，项目原生标注仍可保存，并清楚标出源标签未同步，不能返回笼统的“写回成功”。快照桥接和导出也必须显式检查兼容性。

## 交互

将画布命令集中到可测试的编辑状态模块：创建/完成/取消草稿，命中测试，选中/多选，移动/缩放/顶点编辑，顶点插入删除，复制、删除、撤销/重做。一次拖拽或一批 AI 结果只占一条历史。标签列表与画布选择同步。新形状完成时从项目类别中选择标签，并允许沿用上次标签。图片队列分页加载，不能把前 120 张当作全项目；缩略条跟随当前图片。切换、关闭和导航统一处理脏状态。验证状态由后端持久化。

## AI

参考仓库的 `cpp/tools/onnx_detection_bridge.py` 和 `cpp/tools/labelme_ai_bridge.py` 由可取消的本地进程调用，保留原 MIT 许可证和来源说明；不在 UI 线程推理。ONNX 支持参考实现列出的 YOLOv5、YOLOv8/11 与 end-to-end 检测布局。OSAM 支持正/负点、框和文本提示，以及参考实现的输出形状。前端先显示依赖/模型状态和进度；Rust 限制输入路径、参数和执行时间，并验证所有返回坐标、类型、类别与掩码，再一次性加入当前图片。取消、错误、页面切换或过期响应不改变标注。模型下载应由用户明确触发。

## 验收

以参考仓库形状和格式样本做往返测试；覆盖所有画布模式的创建、编辑、撤销/重做、图片边界和快捷键。以模拟 Python 输出测试 AI 进度、取消、损坏结果和重复抑制；有依赖/模型时再做真实推理烟测。真实数据集检查 YOLO/VOC 写回、原生 JSON、快照与导出，特别验证不兼容形状不会悄悄消失。测试和构建通过后按功能批次提交；每批维护能力对照表，直到表中的目标全部通过。
