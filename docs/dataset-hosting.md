# 数据集托管

数据集托管把已发布项目中的图片、原图引用和标注快照组织成同一组织可复用的云端数据资产。身份、ACL、版本、异步任务和配额均由服务端管理；本地工作区仍是客户端缓存与编辑入口，不能把本地缓存 ID 当成服务端项目 ID。

## 从哪里进入

- 桌面端：在协同面板打开“数据集托管”。
- 移动端：在项目页打开“数据集托管”，使用移动安全布局；移动端托管入口不改变项目、任务和审阅主流程。

两端都通过 Rust 的认证 `remote_request`/托管 IPC 访问服务器，不在浏览器或 WebView 中保存、拼接或暴露访问令牌。桌面端继续保留批量导入导出和本地 AI 能力；移动端不承诺本地 AI 或桌面批处理能力。

## 基本工作流

### 新建、编辑和归档

1. 在“我的数据集”中选择“新建数据集”，填写名称和描述。
2. 所有者或管理员可以编辑名称/描述；更新带有 `baseRevision`，服务端发现并发修改时返回修订冲突，而不是静默覆盖。
3. 只有所有者可以归档。归档是软删除：数据集、版本、原图对象、标注资源以及保留的导入/导出文件不会立即物理清除，清理完成前仍计入组织配额。

### 成员和组织权限

数据集成员必须属于同一组织。成员输入框支持邮箱或用户 UUID：输入邮箱时客户端发送 `{email, role}`，输入 UUID 时发送 `{userId, role}`；普通用户不需要先查内部 UUID。权限角色如下：

| 角色 | 能力 |
| --- | --- |
| 所有者 | 查看、编辑、收录、建版本、复用、导入/导出、成员管理、归档；组织所有者可调组织配额 |
| 管理员 | 查看、编辑、收录、建版本、复用、导入；可按权限管理成员；不能归档数据集 |
| 查看者 | 查看数据集、成员、版本、任务和导出；可在自己对目标项目拥有 `ManageData` 权限时复用到已有项目，也可复用为自己新建项目；不能改数据集或成员 |

“管理员”是数据集角色，不等于组织所有者。配额面板会明确显示“可管理/只读”；没有权限时不会显示配额保存入口。

### 从已发布项目收录

“收录远端项目”只列出服务器返回的远端项目 UUID，并限制为有 `ManageData` 能力的项目。收录会复制项目元数据和标注 JSON 到数据集条目，同时复用相同原图对象的内容引用，避免重复上传相同原图字节。

每次收录、建版本和复用都带一个 `operationId`。同一个操作在网络重试或进程恢复时必须复用同一个 ID；相同请求会返回原结果，不会重复写入。把新请求误用旧 ID 且请求内容不同会得到 `OPERATION_ID_REUSED`/冲突，而不是覆盖旧操作。

### 不可变版本

“创建版本”会把当前数据集条目写入一个带 manifest/hash 的版本快照。版本创建后不可编辑、不可覆盖；后续收录或标注变化只会产生新的数据集修订或新版本。版本详情可查看 manifest，版本列表可用于导出和复用。

版本保存的是某一时刻的条目、原图引用和标注快照。原图对象按内容在组织范围内共享，复用版本到新项目或已有项目时不会再次上传相同原图；复用产生的项目标注行是独立副本，之后在项目中修改标注不会回写旧版本，也不会改变其他项目的标注。

### 复用到项目

可以新建项目，也可以选择服务器返回的远端项目 UUID。客户端绝不把本地缓存 ID 作为 `targetProjectId` 发给服务器；复用已有远端项目成功后，调用远端项目 hydrate/open，取得对应的 `localProjectId`，再沿用本地打开入口。这样不会为已经缓存的项目重复创建另一份本地缓存。

## ZIP 导入、异步任务和导出

导入和导出都由持久化的服务端 job 表管理。上传/请求成功只代表任务进入队列；进程重启后任务状态仍可查询。面板会轮询任务状态并展示排队、处理中、完成或失败及错误信息。失败格式、校验、权限、配额和内容错误必须显示为失败，不能当作成功上传。

### 导入格式和限制

界面支持以下格式：

- `native`：Image-Annotation 原生 manifest/标注格式；
- `coco`：COCO JSON，支持 bbox 和 polygon；
- `yolo`：YOLO 检测框；
- `labelme`：LabelMe JSON。

服务端还接受显式的 `yolo-seg`/`yolo-segmentation` API 格式用于 YOLO 多边形分割；它不等于界面下拉框默认的 `yolo` 检测框格式。未知或不支持的格式会显式失败。COCO 不支持的 RLE/不符合约定的多段几何也会失败，不会生成部分数据集。

单个 ZIP 的安全边界：

| 项目 | 限制 |
| --- | ---: |
| 压缩包大小 | 64 MiB |
| 解压后累计大小 | 256 MiB |
| ZIP 条目数量 | 20,000 |

服务端还拒绝路径穿越、绝对路径、符号链接、过高压缩比、非法图片尺寸和不完整标注。上传前客户端会检查 64 MiB；最终解析和配额检查仍以服务端为准。

### 导出和文件位置

选择不可变版本和格式后创建导出 job。任务成功时，原生桥下载 ZIP、校验字节数和 SHA-256，并返回文件名、大小、摘要和本机路径；hash 不匹配会清理临时文件，不保留损坏的“成功”文件。Android 的“查看/保存导出文件”按钮调用原生系统保存/分享面板，避免 WebView 直接导航私有路径；iOS 显示 Files 应用位置，不把私有路径当作下载链接。

- Android：导出位于应用 `app_data/files/exports/<server-account-scope>`，通过 `FileProvider` 打开系统保存/分享面板。
- iOS：导出位于 `Files App → 我的 iPhone/iPad → Image Annotation → Dataset Exports`。
- 桌面：由原生文件管理器 reveal 导出文件；路径和 SHA-256 会显示在导出结果中。

## 组织配额和计量

新组织默认配额为 **10 GiB** 和 **100,000 个逻辑条目**。逻辑条目包括项目图片和数据集托管条目；原图对象按内容共享，重复引用不重复计入原图字节。

计量字节包括服务端实际保留的原图/对象、版本 manifest 与标注 JSON、保留的输入 ZIP、导出 ZIP，以及对应的任务预留字节。导入、收录、建版本和导出会在服务端事务中预留/消费配额。失败任务的对象清理如果暂时失败，已占用或预留的配额会保留，直到后台清理成功；不能把清理失败当成已释放配额。归档数据集保留的资源同样继续占用配额。

配额上限只能由组织所有者在有权限时调整。客户端不能绕过服务器配额，也不能通过重复提交操作规避资源计量。

## 客户端/服务端边界

托管 API 主要包括：

- `/api/v1/datasets`：列表、新建、编辑、归档、成员、项目收录、版本、复用；
- `/api/v1/storage/quota`：查看和（有权限时）修改组织配额；
- `/api/v1/datasets/{id}/imports`、`/exports`：创建导入/导出任务；
- `/api/v1/datasets/{id}/jobs`、`/api/v1/dataset-jobs/{jobId}`：查询任务；
- `/api/v1/dataset-jobs/{jobId}/download`：服务端导出流；原生客户端通过认证桥完成下载和校验。

写请求不使用通用自动重试；只有读取请求对明确的暂态响应有限重试。收录、版本、复用、导入、导出必须由调用方在同一次用户操作中固定 `operationId`，重试时复用它。
